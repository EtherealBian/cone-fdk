# ConeFDK · 原生版本性能对照

同一台 RTX 5060 Laptop；比较旧发布版与当前发布版，不是与 ASTRA 比速度。输出固定为 512³ FP32（512 MiB），显存预算 768 MiB，每批 16 角。两版都先各热身一次，再开独立进程交替跑 6 对，保留全部结果；没有清 OS/JIT 缓存，也没有锁定 GPU 时钟。两边均写同一目录同一目标、flush、原子替换。哈希在计时外。

|输入|整进程中位数，旧 → 新（s）|耗时降幅|更快的配对|CLI 内部壁钟，旧 → 新（ms）|CUDA 反投影，旧 → 新（ms）|D2H，旧 → 新（ms）|
|---|---:|---:|---:|---:|---:|---:|
|解析体模，180 角|1.198 → 1.128|5.9%|6/6|1124.1 → 1044.2|246.7 → 177.4|127.5 → 41.1|
|实测核桃，720 角|2.392 → 2.009|16.0%|6/6|2288.2 → 1902.4|1147.4 → 793.0|130.5 → 54.4|

进程时间从启动到退出，包含初始化、文件 I/O、同步和退出；CLI 内部壁钟不含退出清理；反投影及 D2H 是 CUDA Event 时间，不能混用。中位数不可逐项相加。两组均通过预设的端到端门槛：耗时中位数至少降低 5%，且至少 80% 的配对更快，内部壁钟也须分别满足。

## 实现与代价

- 旧内核每次采样都读四个独立的像素，再各自计算水平差值。新 CUDA kernel 在每个滤波后的角度批上预计算 `(左值, 右值−左值)`；反投影每层读上下两组 float2。不启用 fast-math，不用硬件近似双线性插值。虚拟左列与每角两个零元素维持原来的探测器外零延拓。
- 编码表复用刚完成逆变换、已不再需要的复数 FFT 缓冲，不额外申请显存。`v*(u+1)+2 ≤ v*k` 对支持的 `u,v ≥ 2, k ≥ 2u` 成立，包含最紧的 2×2。每线程处理 16 个 Z 层，但分为原来的四层小组计算坐标，以保留非二进制体素间距的舍入次序。
- 主机输入与输出暂存每块最多锁页 8 MiB。内存不足时退回普通页，也可用 `--host-memory pageable` 显式禁用。SSE2 检查 FP32 指数位，继续拒绝投影和重建中的非有限值。仍然校验 GPU 哨兵、落盘并原子发布。

720 角实测：打表计入滤波阶段，该阶段中位数从 64.2 到 65.7 ms。新旧设备缓冲峰值同为 554.07 MiB；新版本次另用 13.06 MiB 锁页**主机**内存。设备缓冲精确计数并非整个进程或驱动的显存。

## 数值与复现

- 每份 A/B 输出都作完整 SHA-256，比对通过。完整 720 角核桃对 ASTRA 的全体积相对 L2 为 0.02899%。1296³ 压力体落盘 8,707,129,344 字节且与旧包哈希相同；五个物理切面对 ASTRA 的验证并不等于全体积对照。
