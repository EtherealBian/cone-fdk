# ConeFDK 本机验收记录 · 2026-11-23

**结论：以下预设门槛在本机实跑通过。** 独立 GPU 对照是 ASTRA 2.5.0 `FDK_CUDA` 的 Ram-Lak。精度使用全部体素、物理坐标与绝对衰减值，不乘拟合系数、不配准、不裁剪。真实样本没有实物尺寸真值。

- 平台：Windows 11，build 10.0.26300；NVIDIA GeForce RTX 5060 Laptop GPU, 616.56, 8151 MiB。Python 3.12.16；编译/数值依赖精确版本见 `requirements-win.lock`。
- 构建产物 SHA-256：EXE `658db372cc274083024d68b547297c5f602259d1738b287c63f1282684280dd0`；PTX `8697e37dc4acd3de47ad6454a07db132f7203cbbe0544f2b5d125a684741e122`。
- 原生报告中的 `driver_api=13040` 是驱动所支持的 API 版本，**不等于**生成 PTX 的 NVRTC 版本；本发布构建用 NVRTC 12.9 `compute_80`。cuFFT runtime 返回 `11401`。

## 1 · 解析工件：实现间一致性及物理真值

180 个独立解析投影，160 列 × 128 行，源到等中心 120 mm、到探测器 205 mm、FOV 32 mm。两偏心通孔直径分别为 4.8 和 3.0 mm，夹杂远离中平面。阈值：ASTRA 全体积相对 L2 <1%；均匀材料误差 <3%；中心 <0.4 mm；等效直径误差 <0.6 mm。孔测量来自中心层的半衰减阈值，不代表设备测量不确定度。

|---|---:|---:|---:|---:|---|
|256³|0.02495%|0.11424%|0.00803 / 0.00860|0.00439 / 0.00129|19 MiB / 6 / 0|

## 3 · 相同机器、相同输入的 GPU 性能对照

阶段时间和进程端到端**分别**统计。各分辨率先对两实现热身，再各运行 3 次，中位数如下。GPU Event 只覆盖 native 相应阶段；ASTRA 算法调用包含其内部传输/资源管理，不能从这张表推出纯内核加速比。`native wall` 含 CUDA 初始化、主机输入校验和输出 flush；ASTRA I/O+算法自读投影前起计到写盘和清理结束，不保证有同样的 flush。

|体积|native 滤波 / 反投影 ms|native H2D / D2H ms|native wall ms|ASTRA 算法调用 ms|ASTRA I/O+算法 ms|
|---|---:|---:|---:|---:|---:|
|256³|1.97 / 14.78|2.48 / 6.15|304.0|65.1|334.9|
|512³|3.03 / 170.24|2.47 / 35.86|921.6|398.0|2653.9|

另开进程，双方采用相同外层计时器，每档交替顺序，各 3 次；是**新进程**，不清 OS 文件缓存/驱动 JIT 缓存。ASTRA 的 Python 启动和导入计入该列。通过 Windows WDDM 以约 10 ms 间隔采样实际工作进程的 local GPU memory，表中列出各次峰值的中位数，可能漏掉瞬时尖峰。native 精确计数只覆盖引擎持有的设备缓冲（含 cuFFT 工作区和边界），不包含驱动/上下文。

|体积|新进程端到端 native / ASTRA s|WDDM 峰值 native / ASTRA MiB|native 自有峰值 MiB|
|---|---:|---:|---:|
|256³|0.344 / 2.428|176.00 / 202.00|73.26|
|512³|1.156 / 4.820|624.00 / 650.00|521.26|

256³ 的单次 batch=1→16 消融：反投影启动 180→12 次，反投影 97.82→17.98 ms；这是一次观测，不是跨机保证。[冷进程明细](cold-benchmark.json) · [批量消融](batch-profile.json)。

## 4 · 真正大于整卡的输出

`1296³ × float32 = 8,707,129,344 B`，显卡物理显存 `8,546,942,976 B`。512 MiB 自有预算、实测峰值 **509.02 MiB**，每块最多 78 层，共 **17 块**。native 内部壁钟 12.418 s。确实落盘写出整个体，再读回并哈希；不是估算。SHA-256 `9efb4e96bced3a183a4516a48520bc5ec9a5f42890e40a83792acebc2712dd89`。

独立 ASTRA 校验的层号为 432, 623, 624, 648, 864，包含相邻接缝；最差切面相对 L2 **0.02856%**。这五层不是全体积比较。[原始记录](oversize.json)。

## 5 · 回归与未验证项

- [JUnit](native-tests.xml)：**33 passed，0 skipped**。覆盖异常退出不替换原输出、短/长文件、非有限值和有限数溢出、非法几何、路径和硬链接别名、中文路径、角度反向、非等距探测器像素、自动分块与尾批。
- 小体积测试逐体素对独立 FP64 空间域实现：直接卷积（不使用 FFT）、射线与探测器平面相交、双线性零延拓；覆盖探测器边缘脉冲、非对称随机数据与最小 2×2 探测器，门槛为相对 L2 <5×10⁻⁶、峰值归一最大误差 <10⁻⁵。该实现只用于测试。
- 离线 HTML 另有回归：校验预览层号、PNG 的尺寸、解码与完整性，且不允许模板替换污染二进制载荷。发布包在干净目录的演示复测记录单列于包旁的 `verification.json`。
- 本次成功输出均验证 GPU 缓冲前后边界哨兵；它不能覆盖所有越界读写。另尝试的 NVIDIA Compute Sanitizer 未能附着目标进程；[原始日志](sanitizer-memcheck.txt)。**不将 memcheck 计为通过，也不声称已做完整内存安全证明。**
- 在这台 Windows 单 GPU 上复现，不构成跨设备认证、缺陷检出概率或计量/临床合规证明。
