# 两个锚点之间，证据支持什么结论？

`anchor_audit.py` 从已有离线控制台读取标签，在材料坐标中回答“这两格是否由超限格连通”。无需 CUDA、NumPy、SciPy、浏览器或联网；不需要重新测量，也不会改变已选的损失门槛。每种全局设置单独计算，不把不同图中的超限格拼成一条不存在的通路。

```powershell
# 仓库的窄桥控制台示例；其他文件请从可信交付记录取得整文件指纹。
python -I -S scripts/anchor_audit.py reports/bridge-console.html critical-a build/my-anchor-audit.json --start 11 46 --end 29 46 --console-sha256 b60f228f73fa90131a54281002ed2a00c81032ed9ed7a81dea0857deadf44941
```

坐标为从零开始的 **轴向行、方位列**，只在列上周期相邻。输出必须是新文件，父目录应存在且支持硬链接。先核对整份 HTML 的外部指纹，再核对选中作业的每幅标签图、覆盖与阈值对。拒测作业没有地图，不会显示上一件的结果。

| 状态 | 可以得出的结论 |
|---|---|
| `observed_link` | 存在一条完全由已测超限格组成的连接。图上别处有盲区并不抹掉这项证据。 |
| `separated_on_grid` | 即使把所有不可测格都暂视作超限，两个端点仍不能通过本次采样网格连通；**不是**对网格外的陈述。 |
| `unresolved_blind_path` | 连通需要把至少一个未知格假定成超限。给出完成一条路径至少要补证几格，但不把它当作实测连接。 |
| `anchor_below_gate` | 至少一个锚点本身已测为低于门槛，不是两个已超限区域之间的连接问题。 |

路径先最小化经过的未知格数（含端点），再在同成本解中取步数最短者。坐标和阈值对可以复核；同样短的路径可能不止一条。结果保存路径方向和长度、行主序格号的 int32 小端 SHA-256。超过 256 个方向段只留步数、段数与摘要，可用原图复算。这里的格数既不是概率，也不是最小补扫方案。每张图至多 1,048,576 格，选中作业至多 8,388,608 个配对单元，超限明确拒绝。

## 两个真实运行的离线例子（测量输入仍是模拟数据）

- [临界作业 A](anchor-critical-example.json)：确认 3 种设置有实测通路，另 6 种在网格内断开，可追踪每条路径经过哪些格。没有合并小岛或填洞。
- [不可测边缘对照](anchor-blind-example.json)：其中一对的两个锚点各自属于不同的已测区域 ID **4184、4539**。若要把它们连起来，任何候选路径都至少经过 **5 个不可测格**；证据不是“已断开”，也不是“已连通”。另两种配对连锚点本身也不可测，最少需 7 格；最后一对锚点低于门槛。
- [验收记录](anchor-qualification.json)：逐幅对照 40 个独立原生 CUDA 报告、590,400 个标签单元。独立堆搜索重算最少未知格和最短路径，逐步检查输出路径、端点与摘要。穷举 2×3 周期网格的 **729 种三态图**、每个盲格的全部可能补全并比较两对锚点，另有端点出界、无轴向环绕、损坏格和篡改路径反例。

隔离索引检出已通过历史全验收（含真实核桃、超显存压力和三项投影重放）；在同一检出加入本轮 25 个测试后，整套 **469 passed**。从原生报告再次运行得到相同的资格文件字节。未重新估算 CUDA 加速比。
