# Calibrating the decoder to a signed boundary distance (development only)

Question: does distance to the nearest opposite **archived digital label** teach the raw decoder where the interface is better than just repeating its sign? This is not estimating physical subvoxel distances. Distinct from the singleton mass, local connectivity and gray-image inversion studies. Register independently of the ongoing orientation test; do not use its output, combine methods, select by specimen or tune after the screen.

1. Use only the original calibration masks (2/3/5, x=[360,616), y=[376,632), z=[160,184)). Compute exact three-dimensional Euclidean distance in voxel-center units to the nearest opposite label. Keep only centers at least four lattice steps from each crop face and with distance <=4. This fully observes the radius-four ball without treating the exterior as either class. Target is sign (+ pore, - material) times (distance minus 0.5). This half-step convention is a discrete proxy, not an exact signed distance to a continuous surface. A matched control target is sign times 0.5 on **exactly the same centers**. All other labels still contribute to the unmodified base loss. Before fitting, require each specimen to have >=128 distinct supervised centers on each side, including >=32 per side with distance >1, distributed over >=4 z planes each (for distances >1). Publish these counts, class-specific distance bins, z coverage, crop and target digests; if unsupported, stop rather than weakening the rule.
2. Use the archived ten-channel census input, network, deterministic initialization, complete tile census + common border patches, augmentations, AdamW, LR schedule and 1,536 steps. Two shared networks trained independently from the same initialization. Original BCE plus 0.1 relative patch-area loss unchanged. Add 0.25 times mean smooth-L1 (beta=1) between `logit/2` and the arm target over valid centers pooled within the six patches. Empty band in a batch: zero auxiliary term. No balancing/extra samples, distance input, threshold search, orientation average or postprocessing. Arms: `sign` (control), `distance` (treatment). Archive optimizer traces, stream digests, common initialization and both weights. Threshold once at logit >=0. Use previously sealed, **unmodified** `census` predictions as a third comparator, not a training target.
3. For the previously seen transfer region z=[256,352) only, record native CUDA masks and an independent float64 convolution after the shared frontend, for every signed/unsigned decision; record max logit differences and first disagreement. Publicly seal software/weight/source identities and six masks before scoring labels. No reserve or formal samples. Run the same native 8/37 checks and independent component/match counts on all three arms. Publish eleven metrics per arm, gains/losses by reference ID, all- and shared-match P95, and both coverage denominators.
4. Primary: versus **each** comparator, >=5 shared matches with >=2 percentage-point gain in same-ID volume P95 on **each** specimen, neither coverage fraction drops and Dice loss <=.002; zero CPU/native decision differences for the new masks. Additionally require all-matches volume P95 not to increase versus either comparator on any specimen. Otherwise close this loss contrast without fitting a new coefficient/width or applying the better-looking arm to selected specimens. Passing this transfer screen is not passing FINAL-GATE. Formal testing, independent replay, public candidate freeze and protected 4/6 order unchanged.
