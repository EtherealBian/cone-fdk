# Patch-statistic preselection — development calibration only

F did not clear FINAL-GATE. Instead of tuning F on the formal errors, test a different assumption about the source-like image filter: do patches with a similar squared distance but incompatible local mean or variance blur a pore boundary? This is an original 2-D adaptation of the patch preselection idea in Coupé et al., DOI 10.1109/TMI.2007.906087, not a claim that Avizo uses it.

Use only development 2,3,5. Keep the 27-voxel median, dense 21×21 plane search with uniform 5×5 squared-distance weights, NIST's post-denoise 8-bit conversion and Bernsen rule. Compare unconstrained native CUDA NLM against the same estimator admitting only neighbors for which min(mean)/max(mean) >= .95 and min(variance)/max(variance) >= .50 (both zero admissible). Ratios use native uint16 intensity, not the shifted 8-bit domain. Include self. The three bandwidth candidates 20, 30, 40 are expressed in mapped units. No topology edit, threshold correction or postprocessing.

Pick bandwidth separately per arm/scan solely by Dice on x=[360,464), y=[376,632), z=[160,168) (first/smallest on ties). Evaluate the selected pair on x=[512,616), y=[376,632), z=[176,184); labels and source dependencies do not overlap between windows. Retain all fit scores, confusion counts, both check decisions and FP/FN transitions. Advance only if each scan gains >=0.005 check Dice without reducing either precision or recall by more than 0.005. This gate only controls follow-up; it cannot certify 3-D pore measurements. No formal ROI or reserve reads for this test.
