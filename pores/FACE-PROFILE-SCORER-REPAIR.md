# Post-seal scorer repair, no detector or ranker change

The first and repeated scoring attempts against the 7bc8c69 seal stopped during the first specimen, before writing a specimen report: the native in-memory reference ID is an integer, while the previously published interval JSON uses string keys. Both raised `KeyError: 10` in `diagnostic`; native tables for this specimen had already been generated. We do not call the restarted scoring previously unopened. The repair converts only the lookup key to `str(rid)`; it does not change numerical comparisons, inference, training, eligibility, thresholds or the protocol. Because scorer code is included in the pipeline identity, replay the full raw fit and inference twice and republish the updated manifest. Require byte-identical model, object decisions and predictions versus the original seal; retain both identities and all comparisons. Then re-score all specimens from scratch into two new directories.
